# VS Code Remote SSH 场景下的代理配置方法

这篇笔记记录一种在 `VS Code Remote SSH` 场景下，让远程开发环境通过本地代理访问外部网络的常见做法。

它适合这样的场景：

- 远程服务器网络环境受限
- 某些开发工具或扩展需要通过代理访问外部服务
- 你希望把本地电脑已有的代理能力转发给远程开发会话使用

## 原理说明

核心思路是使用 `SSH 反向隧道`，把本地机器上的代理端口映射到远程服务器。

数据流向如下：

```text
远程开发环境 -> SSH 反向隧道 -> 本地代理 -> 外部网络服务
```

这样做的好处是：

- 不需要在远程服务器单独安装一套代理工具
- 复用本地已经配置好的网络出口
- 对 `VS Code Remote SSH` 工作流比较友好

## 前置条件

开始前请确认：

- 本地电脑已经安装并配置好可用代理
- 本地代理监听端口为 `7890`
- 你可以正常通过 `SSH` 登录远程服务器
- 远程开发使用的是 `VS Code Remote SSH`

如果你的本地代理端口不是 `7890`，请把下面示例里的端口一起替换掉。

## 第一步：本地代理允许局域网访问

如果你使用的是图形代理客户端，先确认已经开启允许局域网访问功能。

以常见客户端为例，一般需要打开类似下面的选项：

- `Allow LAN`
- `允许局域网连接`

这一步的目的是让本地代理端口可以被 SSH 隧道正常转发使用。

## 第二步：建立 SSH 反向隧道

在本地终端执行：

```bash
ssh -R 7890:127.0.0.1:7890 root@你的服务器IP
```

参数含义：

- `-R 7890:127.0.0.1:7890`
  表示把远程服务器上的 `7890` 端口，反向映射到你本地电脑的 `127.0.0.1:7890`
- `root@你的服务器IP`
  替换成你自己的 SSH 登录账号和服务器地址

建立成功后，请保持这个终端窗口不要关闭。

## 第三步：配置 VS Code Remote SSH 的远程环境变量

连接远程服务器后，在 VS Code 中按：

```text
Ctrl + Shift + P
```

然后打开：

```text
Preferences: Open Remote Settings (JSON)
```

填入下面的配置：

```json
{
  "claudeCode.environmentVariables": [
    {
      "name": "HTTPS_PROXY",
      "value": "http://127.0.0.1:7890"
    },
    {
      "name": "HTTP_PROXY",
      "value": "http://127.0.0.1:7890"
    }
  ]
}
```

如果你配置的是其他依赖代理的命令行工具，也可以采用同样思路，把它们需要的代理环境变量写到远程环境里。

## 第四步：在远程环境中安装或使用所需工具

完成代理配置后，就可以在远程开发环境里安装或使用依赖外部网络的工具、扩展或命令行程序。

如果你使用的是某个 VS Code 扩展，请确认它安装在远程环境而不是本地环境。

通常可以在扩展页中选择类似：

```text
Install in SSH
```

## 静默启动 + 自动重连方案

如果你不希望开机后弹出命令行窗口，同时又希望 SSH 隧道断开后能自动重连，可以使用 `VBScript` 在后台循环启动命令。

### 第一步：创建 `ssh_tunnel.vbs`

新建 `ssh_tunnel.vbs`，内容如下：

```vbs
Set WshShell = CreateObject("WScript.Shell")

Do
    WshShell.Run "cmd /c ssh -o ServerAliveInterval=60 -o ExitOnForwardFailure=yes -R 7890:127.0.0.1:7890 root@你的服务器IP", 0, True
    WScript.Sleep 5000
Loop
```

请把其中的 `root@你的服务器IP` 替换成你自己的登录信息。

### 参数说明

- `cmd /c`
  表示执行一次命令后退出
- `0`
  表示隐藏窗口运行，不显示黑色命令行窗口
- `True`
  表示等待当前 SSH 进程结束后，再继续执行下一轮循环
- `WScript.Sleep 5000`
  表示断开后等待 5 秒再自动重连

### 第二步：放入开机启动目录

在 Windows 中按：

```text
Win + R
```

输入：

```text
shell:startup
```

把 `ssh_tunnel.vbs` 放进打开的启动目录。

### 第三步：删除旧的启动脚本

如果你之前已经把 `ssh_tunnel.bat` 放进了 `shell:startup`，请把旧的 `.bat` 文件从启动目录中删除，避免重复启动。

## 这种方式的优点

- 开机后静默运行，不弹出黑窗口
- SSH 隧道断开后会自动重连
- 适合长期作为本地启动项使用

## 注意事项

- 本地代理程序仍然需要保持开启
- SSH 登录信息必须有效
- 如果你使用密码登录，某些情况下仍可能需要人工输入密码
- 更推荐配置 SSH 密钥登录，这样自动重连会更稳定

## 常见问题排查

### 1. 隧道建立后仍然无法访问

可以先检查：

- 本地代理是否真的监听在 `7890`
- 本地代理是否开启了局域网访问
- SSH 会话是否仍然保持连接
- 远程环境变量是否写在 Remote Settings 而不是本地 Settings

### 2. 工具仍然没有走代理

有些工具只识别特定环境变量，常见包括：

- `HTTP_PROXY`
- `HTTPS_PROXY`
- `ALL_PROXY`

可以根据具体工具文档补充对应配置。

### 3. 远程端口被占用

如果远程机器上的 `7890` 已被占用，可以换成其他端口，例如：

```bash
ssh -R 7891:127.0.0.1:7890 root@你的服务器IP
```

然后把远程配置中的代理地址同步改成：

```text
http://127.0.0.1:7891
```

## 总结

这种方式本质上是把本地网络出口能力，通过 `SSH 反向隧道` 交给远程开发环境使用。

对于 `VS Code Remote SSH`、远程扩展安装、远程命令行开发等场景来说，这是一种实用而且通用的代理配置方法。
